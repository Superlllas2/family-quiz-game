# Decision record 0018: the pause menu and question feedback

Date: Nov 6, 2026. After the question bank audit (`docs/question_audit/README.md`), Ilia asked for a way to measure how each question plays with the real audience: a setting in the TV app that, after each question, lets every player rate it from 1 to 5 stars on their phone, closable, with the AI choosing what to ask. He also asked for an Escape menu on the laptop with Resume, rerun the game and Settings. Ilia's answers: each player rates on their own phone; the Escape menu pauses the game; "rerun" means abandon this game and start a new one with the same players. The AI building the game never reopens one of these on its own; it asks first.

| # | Question | Decision | Replaces |
| --- | --- | --- | --- |
| D105 | The Escape menu | Escape on the laptop opens the pause menu over the TV: **Continue**, **New game**, **Settings**. Escape again or Continue closes it. While it is open the game is paused: the core clock stands still (the same pause as a lost relay, so no phase, deadline, seat hold or host line moves on) and every phone shows `paused`. It works in every phase | Nothing (Escape did nothing) |
| D106 | Tab and Settings | The Tab panel still opens at any time without pausing (0002 unchanged). Settings in the pause menu opens the same panel while the game stays paused; closing the panel shows the pause menu again | |
| D107 | New game | Abandons the running game (`gameEnded` reason `restart`), returns everyone to the Lobby like Back to lobby, then marks ready every connected player who has a character, so with `players.min` or more connected the StartCountdown starts at once and the new game skips the Intro like any next game. It takes a confirming second click within 4 s, like Back to lobby, and resumes the clock. Hidden in the Lobby | |
| D108 | The feedback setting | A row in the TV settings panel, "Оценка вопросов / Question feedback", on or off. Default `feedback.enabled` (off). Takes effect at once, from the next Reveal; logged as `settingsChanged` setting `feedback` | |
| D109 | The rating card | While feedback is on, in the Reveal and Scores of every round question (not the race statements), every phone's screen carries a `rate` object and the phone shows a card over its screen: a title, a close button and one row of 5 stars per item. The leftmost star is 1 of 5, the rightmost 5 of 5. Every tap is sent at once (`input` kind `rate`) and can be changed until Scores ends; the TV keeps the latest per player and item. Closing the card hides it for this question only. The card never extends a phase: it goes when Scores ends. The power up pick stays under the card and works as before. The TV shows nothing of the ratings during the game | |
| D110 | What players are asked | Three items, each optional: **`fun`** "Понравился вопрос? / Did you like the question?" (1 Скучно / Boring, 5 Отлично / Loved it): the outcome the bank is tuned for. **`guess`** "Можно было догадаться, не зная? / Could you work it out without knowing?" (1 Никак / No way, 5 Легко / Easily): educated guessability, which separates "hard but fair" from "random", the audit's second most weighted criterion and the main gap of the hard tier. **`fact`** "Интересный ответ? / Was the answer interesting?" (1 Ну и что / So what, 5 Вау! / Wow!): surprise and payoff of the answer and its "Why?" fact, the bank's weakest and strongest criteria. Difficulty and familiarity are not asked: difficulty comes from the answers (share correct, distance), and three rows fit the 7 s of Reveal and Scores. The items and the star count live in `content/config.json` (`feedback.items`, `feedback.stars`), the texts in `ui_strings.json` | |
| D111 | The log | Every accepted tap is a `questionRated` line: player, question id, topic, format, difficulty, item, stars, and whether that player answered correctly. Pauses are logged as `gamePaused` and `gameResumed` (the log time `t` runs on the core clock, so a pause takes no log time). `tools/analyze_ratings.mjs` sums one or more logs per question, topic, difficulty and format, and joins the audit's scores where a question was audited | |
| D112 | Answer time and the pause | An answer's `ms` leaves out the time the phone showed `paused`: a pause never costs speed points. On Continue every phone gets its current screen again with the same `phaseId` and a fresh `endsInMs` | |

Protocol: the `rate` input kind, the `paused` screen and the optional `rate` field are additions, so the version stays 2 (`PROTOCOL.md` section 7). The phone page needs a new deploy before phones show the card; an old page ignores the `rate` field and shows `paused` as an unknown screen.
