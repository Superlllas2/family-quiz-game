# PROTOCOL.md

Status: Done for game night 1 (Nov 2, 2026). Protocol version: **1**.

The single source of truth for every message between the phone page, the relay and the TV app. Both sides are checked against this file. Changing it requires asking Ilia first (`CLAUDE.md`).

## 1. The three programs

```
Phone page (browser)  <--WebSocket-->  Relay (Cloudflare)  <--WebSocket-->  TV app (Unity)
```

- The **relay** knows rooms and connections, nothing about quizzes. It forwards messages and tells the TV app when phones connect and disconnect.
- The **TV app** owns every rule. It sends each phone the screen to draw.
- The **phone page** draws screens and sends inputs.

All messages are JSON text frames, UTF 8. Every message from the phone or the TV app carries `"v": 1`.

## 2. Relay

### URLs

| Purpose | URL |
| --- | --- |
| Phone page | `https://<relay-host>/?room=ABCD` (the QR code encodes this) |
| TV app socket | `wss://<relay-host>/ws/tv?room=ABCD&secret=<tvSecret>` |
| Phone socket | `wss://<relay-host>/ws/phone?room=ABCD` |

- `<relay-host>` is set in the TV app config (`relayHost`, not in `content/config.json` but in `unity/Assets/StreamingAssets/local.json`) and in the phone build (`VITE_RELAY_HOST`).
- Room codes are 4 uppercase letters from `ABCDEFGHJKLMNPQRSTUVWXYZ` (no I or O), generated by the TV app.
- `tvSecret` is a random 32 character string generated by the TV app per room. The first TV connection to a room code claims it with its secret; a later TV connection with the same code must present the same secret (lets the TV app reconnect). A different secret gets close code 4001.
- A phone connecting to a room with no TV gets close code 4004.
- Rooms close 10 minutes after the TV disconnects.

### Envelope between relay and TV app

The relay never changes the inner message. It wraps it.

Relay to TV app:

```json
{ "relay": "connected", "conn": "c_7f3a9b" }
{ "relay": "disconnected", "conn": "c_7f3a9b" }
{ "relay": "message", "conn": "c_7f3a9b", "msg": { "v": 1, "type": "join", "...": "..." } }
```

TV app to relay:

```json
{ "to": "c_7f3a9b", "msg": { "v": 1, "type": "screen", "...": "..." } }
{ "to": "all", "msg": { "...": "..." } }
```

- `conn` is a connection id made by the relay. A new socket after a reload gets a new `conn`; the player is matched again through `rejoin`.
- Between relay and phone there is no envelope: the phone sends and receives the inner `msg` only.
- Limits: messages over 8 KB are dropped by the relay. A phone may send at most 20 messages per second.

## 3. Phone to TV app messages

| type | Fields | When |
| --- | --- | --- |
| `join` | `name` (1 to 16 chars), `lang` (`ru` or `en`) | First join |
| `rejoin` | `token` | After a reload or reconnect, if a token is stored |
| `avatar` | `avatarId` (0 to 11) | On `pickAvatar` |
| `input` | `inputId`, `phaseId`, `kind`, plus kind fields (below) | Any player decision |
| `settings` | `lang`, `timerMultiplier` (1, 1.5 or 2) | Settings changed |
| `host` | `inputId`, `action`, optional fields | Host phone actions |
| `poll` | `inputId`, `answers` (object) | Poll submitted |
| `ping` | `t` (phone ms since page load) | Every 5 s |

### `input` kinds

| kind | Extra fields | Example |
| --- | --- | --- |
| `vote` | `door` (0 to 3) | `{"v":1,"type":"input","inputId":"a1","phaseId":14,"kind":"vote","door":2}` |
| `choice` | `choice` (0 to 3, index in the displayed order), `ms` | `{"v":1,"type":"input","inputId":"a2","phaseId":16,"kind":"choice","choice":1,"ms":3410}` |
| `value` | `value` (number), `ms` | `{"v":1,"type":"input","inputId":"a3","phaseId":31,"kind":"value","value":1889,"ms":11200}` |
| `trueFalse` | `answer` (true or false), `ms` | `{"v":1,"type":"input","inputId":"a4","phaseId":80,"kind":"trueFalse","answer":true,"ms":2100}` |
| `prediction` | `playerId` | Intro prediction |
| `powerUp` | `powerUp` (`freeze`, `slime`, `fog`), `target` (playerId) | During Reveal and Scores |
| `effectCleared` | `effect`, `ms` (time to clear) | When a sabotage overlay is cleared, for telemetry |

- `inputId`: a short random string made by the phone, unique per input. Resends use the same id; the TV app answers a duplicate with the same `ack` and does not apply it twice.
- `phaseId`: the id from the `screen` message the input answers. An input with an old `phaseId` is refused with reason `stale`.
- `ms`: milliseconds from the moment the options became tappable on this phone (after any sabotage overlay is cleared, the clock keeps running) to the tap. Measured with `performance.now()`.

### `host` actions

`start`, `skip`, `continue`, `finishPoll`, `playAgain`, `newPlayers`, `setGameLang` (field `lang`), `setPowerUps` (field `enabled`), `setTargeting` (field `targeting`: `free` or `aimUp`). Refused with reason `notHost` if not from the host phone.

## 4. TV app to phone messages

| type | Fields | When |
| --- | --- | --- |
| `welcome` | `playerId`, `token`, `isHost`, `room` | After a successful `join` or `rejoin` |
| `refused` | `reason`: `roomFull`, `nameTaken`, `badName`, `gameStarted`, `badToken`, `badVersion` | Join or rejoin failed |
| `snapshot` | `player`, `screen` | Right after `welcome`, and whenever the phone needs a full refresh |
| `screen` | `phaseId`, `id`, `endsInMs` (or null), `data` | Every time this phone's screen changes |
| `ack` | `inputId`, `ok`, `reason` (if not ok) | After every `input`, `host`, `poll` |
| `effect` | `effect`, `from` (name), `params` | Sabotage starts on this phone, at the start of an Answer phase |
| `player` | the `player` object | When score, rank, held power up, host status or settings change |
| `pong` | `t` (echo), `tv` (TV clock ms) | Reply to `ping` |

- `gameStarted`: a new name cannot join during a game; it may join at the next Lobby. A `rejoin` with a valid token always works.
- `token`: random 24 characters, stored by the phone in `localStorage` under `fq.token.<room>`. Valid while the seat is held (`players.seatHoldSeconds`).
- `endsInMs`: how long the phase has left when the message was sent. The phone shows a countdown from it; it is only for display. The TV app decides when a phase ends.
- Ack reasons: `stale`, `closed` (phase over), `duplicate` (already applied; still `ok: true`), `notHost`, `invalid`, `immune` (power up target cannot be hit), `noPowerUp`.

### The `player` object

```json
{
  "playerId": "p3",
  "name": "Mama",
  "avatarId": 4,
  "lang": "ru",
  "isHost": false,
  "score": 2350,
  "rank": 2,
  "streak": 1,
  "heldPowerUp": "freeze",
  "timerMultiplier": 1
}
```

### `screen.data` per screen id

All texts are already in the player's language. Screens not listed have `data: {}`.

| id | data |
| --- | --- |
| `lobby` | `players`: list of `{playerId, name, avatarId}`; host phone also gets `settings`: `{gameLang, powerUps, targeting}` |
| `pickAvatar` | `taken`: list of avatar ids |
| `getReady` | `text`, optional `prediction`: list of `{playerId, name}`, `canSkip` (bool, host only) |
| `topicVote` | `doors`: list of 4 `{title}` |
| `answerChoice` | `question`, `options`: list of 4 strings in display order, `windowMs` |
| `answerSlider` | `question`, `min`, `max`, `step`, `unit`, `windowMs` |
| `answerTrueFalse` | `statement`, `windowMs` |
| `waiting` | `locked`: text of what was locked, `pending`: list of `{name, avatarId}` still answering |
| `result` | `correct` (bool), `points`, `correctText`, `streak`, `rank`, `powerUp` (or null), `targets`: list of `{playerId, name, available}` |
| `roundEnd` | `rank`, `score`, `nextRound` |
| `raceResult` | `correct`, `position`, `finish` |
| `results` | `place`, `correctCount`, `awards`: list of strings, `canContinue` |
| `poll` | `questions`: list of `{id, text, kind, options}` (kinds in `20_playtest.md`) |
| `pollDone` | `canChoose` (host only) |
| `error` | `text` |

## 5. Reconnects

1. The phone stores `token` per room in `localStorage`.
2. On load, on `visibilitychange` to visible, and when the socket closes, the phone opens a new socket and sends `rejoin` with the token.
3. The TV app answers `welcome`, then `snapshot` with the current screen and remaining time.
4. While a player is disconnected, the TV shows a sleeping badge on their avatar, and phases do not wait for them: "every connected player answered" ignores disconnected players.
5. After `players.seatHoldSeconds` (300 s) the seat is freed.

## 6. Clock and timing

- The TV app owns time. Phase ends are decided only by the core clock.
- Scoring uses the phone's `ms`, clamped to 0 to `windowMs`. The TV app also checks that the input arrived while the phase was open plus 500 ms of grace for network delay; later inputs get `closed`.
- `ping`/`pong` measures round trip time per phone for telemetry. Game night 1 does not need clock offset correction.

## 7. Versioning

Every message carries `v`. The TV app refuses a phone with a different major version with `refused` reason `badVersion` and the phone shows "Обнови страницу / Please reload the page". Adding an optional field does not change `v`; renaming or removing one does.
