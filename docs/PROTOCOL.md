# PROTOCOL.md

Status: Done for game night 1 (Nov 2, 2026; revised after the spec review, `decisions/0002_spec_review.md`; avatar renamed to character in `decisions/0005_staging_answers.md`, version unchanged because nothing was built yet; the phone became input only in `decisions/0013_day3_answers.md` (D88), version 2 because screen fields and screens were removed; the pause and question feedback additions of `decisions/0018_pause_menu_and_question_feedback.md` (Nov 6, 2026) keep version 2). Protocol version: **2**.

The single source of truth for every message between the phone page, the relay and the TV app. Both sides are checked against this file. Changing it requires asking Ilia first (`CLAUDE.md`).

## 1. The three programs

```
Phone page (browser)  <--WebSocket-->  Relay (Cloudflare)  <--WebSocket-->  TV app (Unity)
```

- The **relay** knows rooms and connections, nothing about quizzes. It forwards messages and tells the TV app when phones connect and disconnect, and tells phones when the TV app is away.
- The **TV app** owns every rule. It sends each phone the screen to draw.
- The **phone page** draws screens and sends inputs.

All messages are JSON text frames, UTF 8. Every message from the phone or the TV app carries `"v": 2`. There is no host phone: every player may send every message below.

## 2. Relay

### URLs

| Purpose | URL |
| --- | --- |
| Phone page | `https://<relay-host>/?room=ABCD` (the QR code encodes this) |
| TV app socket | `wss://<relay-host>/ws/tv?room=ABCD&secret=<tvSecret>` |
| Phone socket | `wss://<relay-host>/ws/phone?room=ABCD` |

- `<relay-host>` is set in the TV app config (`relayHost`, not in `content/config.json` but in `unity/Assets/StreamingAssets/local.json`) and in the phone build (`VITE_RELAY_HOST`).
- Room codes are 4 uppercase letters from `ABCDEFGHJKLMNPQRSTUVWXYZ` (no I or O), generated by the TV app.
- `tvSecret` is a random 32 character string generated by the TV app per room. The first TV connection to a room code claims it with its secret; a later TV connection with the same code must present the same secret (lets the TV app reconnect). A different secret gets close code 4001.
- A phone connecting to a room with no TV gets close code 4004.
- Rooms close 10 minutes after the TV disconnects; the relay then closes every phone socket in the room with 4004.

### Close codes

| Code | Sent to | Meaning |
| --- | --- | --- |
| 4001 | TV app | Wrong secret for this room |
| 4002 | Phone | Closed by the TV app (a newer socket took this seat). The phone shows the `error` screen "Игра открыта в другой вкладке / Game open in another tab" and does not reconnect |
| 4004 | Phone | No TV in this room, or the room closed |

### Envelope between relay and TV app

The relay never changes the inner message. It wraps it.

Relay to TV app:

```json
{ "relay": "connected", "conn": "c_7f3a9b" }
{ "relay": "disconnected", "conn": "c_7f3a9b" }
{ "relay": "message", "conn": "c_7f3a9b", "msg": { "v": 2, "type": "join", "...": "..." } }
```

TV app to relay:

```json
{ "to": "c_7f3a9b", "msg": { "v": 2, "type": "screen", "...": "..." } }
{ "to": "all", "msg": { "...": "..." } }
{ "close": "c_7f3a9b", "code": 4002 }
```

- `close` is a control message: the relay closes that phone socket with the given code and forwards nothing.
- `conn` is a connection id made by the relay. A new socket after a reload gets a new `conn`; the player is matched again through `rejoin`.
- After the TV app reconnects, the relay sends it one `connected` message for every phone socket still open in the room.
- Between relay and phone there is no envelope: the phone sends and receives the inner `msg` only.

### Relay to phone

The relay itself sends two messages to phones:

| type | When | Phone does |
| --- | --- | --- |
| `tvAway` | The TV app socket closed | Shows `reconnecting` |
| `tvBack` | The TV app reconnected with the right secret | Sends `rejoin` with its token; the TV app answers `welcome` and `snapshot` |

```json
{ "v": 2, "type": "tvAway" }
{ "v": 2, "type": "tvBack" }
```

### Limits

- Messages over 8 KB are dropped by the relay.
- A phone may send at most 20 messages per second. Extra messages are dropped; the socket is never closed for it.
- Phone messages that arrive while no TV app is connected are dropped, not buffered.

## 3. Phone to TV app messages

| type | Fields | When |
| --- | --- | --- |
| `join` | `name`, `lang` (`ru` or `en`) | First join, only in the Lobby |
| `rejoin` | `token` | After a reload or reconnect, or on `tvBack`, if a token is stored |
| `character` | `inputId`, `characterId` (an id from `content/characters.json`, 0 to 15) | On `pickCharacter`. Answered with `ack`; `ok: false`, reason `characterTaken` if another player has it |
| `input` | `inputId`, `phaseId`, `kind`, plus kind fields (below) | Any player decision in a game phase |
| `lobby` | `inputId`, `action`: `ready` or `notReady` | Ready in the Lobby, Not ready in the Lobby or during the countdown |
| `settings` | `lang`, `timerMultiplier` (1, 1.5 or 2) | Settings changed |
| `leave` | `inputId` | Leave game in settings. Frees the seat at once; the player is out for the rest of the game |
| `poll` | `inputId`, `answers` (object) | Poll submitted |
| `ping` | `t` (phone ms since page load) | Every 5 s |

### Names

`name` is trimmed, then must be 1 to 16 characters, each one a Latin letter (A to Z, a to z), a Cyrillic letter (А to Я, а to я, Ё, ё), a digit or a space. Anything else is refused with `badName`. Duplicate names, ignoring case, are refused with `nameTaken`.

### `lobby` actions

| action | Valid when | Effect |
| --- | --- | --- |
| `ready` | Lobby or StartCountdown, the player has picked a character | Marks the player ready (already ready: no change, still `ok`) |
| `notReady` | Lobby or StartCountdown | Clears the player's ready mark (already not ready: no change, still `ok`) |

Any other case gets `ack` with `ok: false`, reason `invalid`.

The TV app starts and stops the countdown itself, never on a tap alone (D76): in the Lobby, the moment every connected player is ready and `players.min` (2) or more players are connected, the countdown (`lobby.startCountdownSeconds`) starts. During it, the moment a connected player is not ready (`notReady`, or a new player joined) or fewer than `players.min` players are connected, it stops and the Lobby comes back. Disconnected players never hold the start up. Ready marks are cleared when a game starts.

### `input` kinds

| kind | Extra fields | Example |
| --- | --- | --- |
| `vote` | `door` (0 to 3) | `{"v":2,"type":"input","inputId":"a1","phaseId":14,"kind":"vote","door":2}` |
| `choice` | `choice` (0 to 3, index in the displayed order), `ms` | `{"v":2,"type":"input","inputId":"a2","phaseId":16,"kind":"choice","choice":1,"ms":3410}` |
| `value` | `value` (number), `ms` | `{"v":2,"type":"input","inputId":"a3","phaseId":31,"kind":"value","value":1889,"ms":11200}` |
| `trueFalse` | `answer` (true or false), `ms` | `{"v":2,"type":"input","inputId":"a4","phaseId":80,"kind":"trueFalse","answer":true,"ms":2100}` |
| `powerUp` | `powerUp` (`freeze`, `slime`, `fog`), `target` (playerId) | During Reveal and Scores (one phaseId) |
| `effectCleared` | `effect`, `ms` (time to clear) | When a sabotage overlay is cleared, for telemetry |
| `rate` | `item` (an id from the screen's `rate.items`), `stars` (1 to 5) | A tap on the rating card in Reveal and Scores (one phaseId), while question feedback is on (D109). Example: `{"v":2,"type":"input","inputId":"r1","phaseId":17,"kind":"rate","item":"fun","stars":4}` |

- `inputId`: a short random string made by the phone, unique per input. Resends use the same id; the TV app answers a duplicate with the same `ack` and does not apply it twice.
- `phaseId`: the id from the `screen` message the input answers. An input with an old `phaseId` is refused with reason `stale`.
- `ms`: milliseconds from the moment the options appeared on this phone to the tap, measured with `performance.now()`, minus the time this phone showed the `paused` screen in between (D112). The clock starts when the options appear, sabotage or not: a sabotage overlay never pauses it. So sabotage costs time, which can cost some speed points (about 100), but never takes points away directly. A new `screen` with the same `phaseId` (last call) does not restart the clock. After a page reload the clock starts when the restored screen is drawn.

### `rate` inputs

- Accepted only in the Reveal and Scores of a round question (not the race) while question feedback is on, with the `phaseId` of that screen; otherwise `stale`, `closed` (the Scores just ended) or `invalid` (feedback off, unknown item, stars not a whole number from 1 to `feedback.stars`).
- A later tap on the same item replaces the earlier one; the TV keeps the latest per player and item and logs every accepted tap.
- Closing the card sends nothing.

### `poll` answers

An object from poll question id to the answer: a string for `text` questions (max 200 characters), an option index (0 based) for `choice` questions. Unanswered questions are left out.

```json
{ "v": 2, "type": "poll", "inputId": "p9", "answers": { "fun": "The freeze on Dad", "waiting": 1, "again": 0 } }
```

## 4. TV app to phone messages

| type | Fields | When |
| --- | --- | --- |
| `welcome` | `playerId`, `token`, `room` | After a successful `join` or `rejoin` |
| `refused` | `reason`: `roomFull`, `nameTaken`, `badName`, `gameStarted`, `badToken`, `badVersion` | Join or rejoin failed |
| `snapshot` | `player`, `screen` | Right after `welcome`, and whenever the phone needs a full refresh |
| `screen` | `phaseId`, `id`, `endsInMs` (or null), `data` | Every time this phone's screen changes, and at last call |
| `ack` | `inputId`, `ok`, `reason` (if not ok) | After every `character`, `input`, `lobby`, `leave`, `poll` |
| `effect` | `effect`, `from` (name), `params` | Sabotage starts on this phone, at the start of an Answer phase |
| `player` | the `player` object | When score, rank, held power up, character or settings change |
| `pong` | `t` (echo), `tv` (TV clock ms) | Reply to `ping` |

- `gameStarted`: a new name cannot join during a game; it may join at the next Lobby. A `rejoin` with a valid token always works while the seat is held.
- `token`: random 24 characters, stored by the phone in `localStorage` under `fq.token.<room>`. Valid while the seat is held (`players.seatHoldSeconds`). A page opened with `&tab=<n>` in the URL (for testing alone with several browser tabs on one computer) stores it under `fq.token.<room>.<n>` instead, so each tab keeps its own seat.
- `endsInMs`: how long this player has left when the message was sent: until their personal deadline in answer phases, until the phase end otherwise. The phone shows a countdown from it; it is only for display. The TV app decides when a phase ends.
- Ack reasons: `stale`, `closed` (past the player's deadline or phase over), `duplicate` (already applied; still `ok: true`), `invalid`, `immune` (power up target cannot be hit), `noPowerUp`, `characterTaken`.
- After `leave` is acked, the phone deletes its token and shows `join`.

### The `player` object

```json
{
  "playerId": "p3",
  "name": "Mama",
  "characterId": 4,
  "lang": "ru",
  "score": 2350,
  "rank": 2,
  "streak": 1,
  "heldPowerUp": "freeze",
  "timerMultiplier": 1
}
```

`rank` is the shared rank (`03_rules.md`): equal scores share the better rank.

### `screen.data` per screen id

All texts are already in the player's language. Screens not listed have `data: {}`.

The phone is an input device (D88): it shows a screen with a decision (join, character, Ready, a vote, an answer, a power up pick, the poll, settings) and `watch` the rest of the time. Questions, statements, results, ranks, scores and the race track are on the TV only.

While the game is paused (the pause menu on the laptop, D105) every phone gets `paused` with the current `phaseId`, whatever the phase; a phone that joins or reloads meanwhile gets it too. On Continue every phone gets its current screen again with the same `phaseId` and a fresh `endsInMs`.

Which screen each phase sends: Lobby `lobby` (or `join`, `pickCharacter`), StartCountdown `countdown`, Intro `watch`, TopicVote `topicVote` then `waiting`, QuestionShow `watch`, Answer the answer screen then `waiting`, Reveal and Scores `watch` (or `result` with a power up), RoundEnd `watch`, FinalIntro `watch`, RaceQuestion `answerTrueFalse` then `waiting`, RaceReveal `watch`, Results `results` to the winner and `watch` to everyone else, Poll `poll` then `pollDone`.

| id | data |
| --- | --- |
| `lobby` | `players`: list of `{playerId, name, characterId, ready}` (`ready`: bool), `ready` (bool: this player is ready), `enoughPlayers` (bool: `players.min` or more players connected) |
| `pickCharacter` | `taken`: list of character ids taken by other players, `current`: this player's character id |
| `countdown` | `text` (`endsInMs` carries the countdown) |
| `watch` | none: "look at the TV" between inputs (D88). In Reveal and Scores it may carry `rate` (below) |
| `topicVote` | `doors`: list of 4 `{title}` |
| `answerChoice` | `options`: list of 4 strings in display order, `windowMs` (the player's personal window). The question is on the TV only |
| `answerSlider` | `min`, `max`, `step`, `unit`, `windowMs`. The question is on the TV only |
| `answerTrueFalse` | `windowMs`. The statement is on the TV only |
| `waiting` | `locked`: text of what was locked. In Reveal and Scores it may carry `rate` |
| `result` | `powerUp`, `targets`: list of `{playerId, name, available}`. Sent in Reveal and Scores only to a player holding a power up (power ups come on Day 4); everyone else gets `watch`. May carry `rate` |
| `results` | `fact`: the winner's reward fact (D87). Sent only to the winner; everyone else gets `watch` |
| `poll` | `questions`: list of `{id, text, kind, options}` (kinds in `15_schemas.md`) |
| `paused` | `text`: "the game is paused" in the player's language (D105) |
| `error` | `text` |

#### The optional `rate` field (D109)

While question feedback is on, the `watch`, `waiting` and `result` screens of Reveal and Scores of a round question carry `rate`; the phone draws the rating card over the screen. Without `rate` there is no card.

```json
"rate": {
  "questionId": "films_old_001",
  "title": "Оцени вопрос",
  "close": "Закрыть",
  "stars": 5,
  "items": [
    { "id": "fun", "text": "Понравился вопрос?", "low": "Скучно", "high": "Отлично", "given": 4 },
    { "id": "guess", "text": "Можно было догадаться, не зная?", "low": "Никак", "high": "Легко", "given": 0 },
    { "id": "fact", "text": "Интересный ответ?", "low": "Ну и что", "high": "Вау!", "given": 0 }
  ]
}
```

- `stars`: how many stars a row has (`feedback.stars`, 5). The leftmost star is 1, the rightmost is `stars`.
- `given`: this player's latest accepted rating for the item, 0 if none (so a reloaded page shows its stars).
- `questionId`: the phone keeps the card closed for the rest of this question once the player closes it, and shows it again for the next question.

Characters come from `content/characters.json` (name and personality line in both languages, signature color); the phone page bundles a copy of that file at build time.

## 5. Reconnects and leaving

1. The phone stores `token` per room in `localStorage`.
2. On load, on `visibilitychange` to visible, when the socket closes (except with 4002), and on `tvBack`, the phone opens a new socket if needed and sends `rejoin` with the token.
3. The TV app answers `welcome`, then `snapshot` with the current screen and remaining time.
4. While a player is disconnected, the TV shows a sleeping badge on their character, and phases do not wait for them: "every connected player answered" ignores disconnected players.
5. After `players.seatHoldSeconds` (300 s) the seat is freed.
6. If a second socket rejoins a seat that already has an open socket (two tabs with the same token), the newer socket wins and the TV app closes the older one with `{"close": "<conn>", "code": 4002}`.
7. `leave` frees the seat at once, the same as an expired hold.

## 6. Clock and timing

- The TV app owns time. Phase ends are decided only by the core clock.
- Each player has a personal deadline in answer phases: window times their timer multiplier, cut to `timers.lastCall` at last call (`03_rules.md`).
- Scoring uses the phone's `ms`, clamped to 0 to the player's personal window (`windowMs`). The TV app accepts an input only if it arrives before the player's personal deadline plus `net.inputGraceMs` (500 ms) of grace for network delay; later inputs get `closed`.
- Votes get the same grace (D84): the vote timer (`timers.topicVote`, the `endsInMs` of `topicVote`) plus `net.inputGraceMs`. The vote still ends the moment every connected player voted.
- `ping`/`pong` measures round trip time per phone for telemetry. Game night 1 does not need clock offset correction.

## 7. Versioning

Every message carries `v`. Version 2 (Nov 3, 2026) removed the `prediction` input, the `getReady`, `roundEnd` and `raceResult` screens and the question and result fields of the phone screens (D88). The TV app refuses a phone with a different major version with `refused` reason `badVersion` and the phone shows "Обнови страницу / Please reload the page". Adding an optional field does not change `v`; renaming or removing one does. This rule applies from the first build: the Nov 2 revision removed the `host` message and the `isHost`, `canSkip`, `canContinue` and `canChoose` fields before any code existed, so the version stays 1.
